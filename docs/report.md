## 摘要

本项目实现了一个面向课程本地验收的在线评测系统。后端采用 FastAPI、SQLAlchemy Async 与 SQLite，前端采用 Streamlit；系统提供用户与角色管理、题目管理、动态语言配置、异步代码评测、提交检索与重测、公开日志与访问审计，以及基于 OpenAI-compatible Chat Completions 协议的可取消 AI 智能命题流程。所有后端路由均为异步接口，响应统一为 `{code, msg, data}`，并根据课程契约返回真实 HTTP 状态码。

判题器在独立临时目录中以参数数组启动编译器或解释器，不使用 `shell=True`。运行期间同时限制时间、递归统计进程树内存、限制输出大小，并在超时或取消后终止整个进程组。系统支持 AC、WA、TLE、MLE、RE、CE 和 UNK，按每个通过测试点 10 分计分。

AI 模块把命题拆分为需求分析、题面与解法、边界测试点、双语言交叉试运行与答案校准等阶段，持续报告进度，统计 Token 与费用，并在保存前通过 Pydantic 结构校验和受限判题器试跑参考解法。API Key 仅加密保存在忽略提交的本机配置文件中，不进入数据库、日志或响应，服务重启后可继续使用。

## 二、系统架构

系统采用浏览器、REST API、业务服务、异步数据库与隔离执行器五层结构。Streamlit 不直接访问数据库，而是通过独立 HTTP Session 调用 REST API 并保存 Cookie；权限判断始终在后端完成。

核心目录如下：

```text

frontend/            Streamlit 页面和 REST 客户端

scripts/             演示数据与报告构建脚本
docs/                报告源稿与线下验收清单
.github/workflows/   Ubuntu + Python 3.10 持续集成
.vscode/             WSL 解释器、运行、调试和测试配置
```

## 三、API 契约与权限设计

### 3.1 统一响应与错误优先级

成功和失败响应均使用 `{code, msg, data}`。FastAPI/Pydantic 的默认 422 被统一转换为 400，使接口严格符合课程契约。组合条件按 `401 > 403 > 400 > 429 > 409 > 404 > 500` 检查，避免同一请求因实现顺序不同而返回不稳定结果。

### 3.2 认证、角色与封禁

登录成功后只在签名 Session Cookie 中保存用户标识，密码使用 bcrypt 哈希；账户中心支持校验当前密码后安全改密。初始化和系统重置都会创建 `admin / admintestpassword`。普通用户可新增和编辑题目且只能访问本人提交；管理员额外负责题目删除与日志公开策略、语言、角色、全部提交和访问审计；被封禁用户即使持有旧会话也会在依赖层被拒绝。

### 3.3 日志可见性与审计

题目支持公开或隐藏测试点日志。管理员始终可查看，普通用户可查看本人提交；题目开启公开后，其他已登录用户也可查看。系统记录资源存在前提下的成功访问和权限拒绝，不记录未登录、参数错误与不存在资源。后台把用户/题目 ID 映射为名称，提供允许、拒绝、涉及用户汇总和最近访问卡片，使权限矩阵可以现场直观核对。

## 四、判题器关键实现

提交接口先写入 `pending` 并立即返回，再由后台任务逐测试点评测。每次提交使用独立临时目录；C++14 先在限制时间内编译，Python 直接解释执行。命令模板会检查占位符、可执行程序白名单和参数形式，最终使用参数数组启动，不经 Shell 解析。

运行阶段并行完成：

1. 等待进程结束并执行硬超时；
2. 使用 psutil 递归统计进程树 RSS；
3. 限制标准输出与错误输出大小；
4. 超时、超内存或取消时终止整个 Linux 进程组；
5. 回收子进程并删除临时目录。

输出比对逐行删除行末空格，并忽略最终多余换行，但保留有意义的前导空格。这样既符合常见 OJ 习惯，也不会把缩进不同的内容误判为相同。

## 五、提交、统计与重置

提交列表支持用户、题目、状态筛选和分页。普通用户只能看到本人提交，管理员可以查看所有记录。每个用户每分钟最多提交 3 次，限流检查位于资源存在性检查之前，以符合错误优先级。重新评测复用同一提交 ID，重置状态与逐点结果后重新进入后台队列。

用户详情统计提交总数与通过题数；通过题数按题目去重，避免同一题多次 AC 被重复计算。系统重置会先取消全部判题和 AI 后台任务，再清空业务数据、重建内置语言和初始管理员，并让当前会话退出。

## 六、AI 智能命题

模型设置包括配置名、兼容接口 URL、模型名、API Key、输入/输出单价、计价单位和币种。每位用户可以保存并选择多个模型；完整配置使用由 `OJ_SESSION_SECRET` 派生的密钥加密写入本机文件，服务重启后无需重新输入。API、数据库和日志只返回是否已配置，不返回密钥本身；系统重置会删除加密配置。OpenAI-compatible 协议没有统一价格接口，单价由用户按服务商账单规则手动确认和填写，因此兼容任意提供商，也避免过期价格造成误导。

AI 任务包含需求分析、题面与参考解法、边界测试点、双语言交叉试运行与答案校准等可观察阶段。隐藏测试点默认由模型结合算法复杂度、边界规模与预计运行时长自动决定 2–10 个，用户也可手动指定数量；样例与隐藏测试点分别存储。模型请求优先采用 OpenAI-compatible SSE 增量响应，前端实时显示当前阶段输出；若兼容服务不支持流式参数，则自动回退普通 Chat Completions 响应。系统按阶段聚合请求次数、输入、输出、思考、缓存和提供商 total Token；思考 Token 已包含在输出 Token 中。若提供商不返回 usage 或失败重试无法计量，界面明确标记估算。DashScope Qwen 可关闭思考模式以显著减少非必要输出 Token。

模型输出必须通过严格的 Pydantic 题目结构校验，并同时提供 Python 3 与 C++14 参考解法。判题器对 C++ 只编译一次，再让两份程序运行全部样例和隐藏测试点；若逐点规范化输出一致，且至少一个模型原始非空答案与共识结果相符，系统把该答案作为题意与下标定义的安全锚点，并以双解共识校准其余错误或空白答案。双解不一致、均执行失败、无安全锚点或输出超限时禁止自动回填，实际状态、输入、stdout 与错误会进入最多两次的修复反馈；仅一种语言失败时只定向修复该语言。校准不调用模型，因此不增加 Token 或费用。解析器仍容忍模型偶发的字符串控制字符，并归一化常见根结构与解法字段别名。取消接口会传播到正在进行的 httpx 流式请求和本地试运行；通过后由服务端把题目作者固定为实际模型名。

## 七、前端与交互

Streamlit 前端在屏幕顶部提供账户概览、题库与评测、提交记录、AI 智能命题和后台管理导航，并显示当前用户名、中文角色与退出按钮；入口按角色精简，权限仍由后端最终裁决。题库与在线评测合并在同一工作区，默认先显示可点击的题库，进入题目后连续展示完整题面、限制、样例、代码编辑器和独立提交按钮；历史记录与详情位于单独的“提交记录”页并按每页 5 条分页。编辑器提供行号、Tab 缩进、括号补全、语法高亮、查找替换和 VS Code 快捷键。每条记录保留 AC、WA、TLE、MLE、RE、CE、UNK 或 Pending 的缩写与中文解释，并使用独立颜色；详情可查看源代码和逐测试点结果。

前端在 `st.session_state` 中保存原生 `httpx.Client`，而不是每次 rerun 都可能因脚本类重新定义而失效的包装器实例。登录、资料、用户、题目、提交、日志、AI 与管理请求因此复用同一 Cookie 容器；退出会同时调用后端 logout 并清理本地 Cookie。通信只使用统一的 `OJ_API_BASE_URL`，登录过期、后端未启动、接口错误、空数据和窄屏均有明确反馈。

AI 模块默认打开“智能命题”，允许从多个已保存配置中选择模型；“模型配置”页展示各模型累计输入/输出 Token 与按手动单价计算的人民币费用。任务完成后先展示题目、参考解法和测试点预览；发生校准时明确显示数量，并提供样例/隐藏测试点、输入、模型原答案和校准答案明细。用户确认后才载入校准后的题目并跳转新增表单，人工审阅步骤不会被绕过。

## 八、测试设计与边界结果

自动化测试覆盖字段校验、错误优先级、会话、角色与封禁、前端 Cookie 跨 rerun/退出回归、题目 CRUD、语言命令安全、筛选分页、限流、统计、日志可见性、访问审计、重置与 AI 工作流。Linux 集成测试真实执行 Python 和 C++，覆盖 AC、WA、RE、CE、TLE、MLE、空白字符比对、重新评测和进程清理。

最终在 Ubuntu 22.04、Python 3.10.12、G++ 11.4.0 环境运行 49 个测试，结果为 49 passed；后端总行覆盖率为 91.40%，超过 CI 设置的 85% 门槛。Ruff 静态检查和格式检查均通过；Edge/Playwright 实际走查管理员与普通用户流程，页面控制台无错误。

AI 测试使用本地假提供商，覆盖成功、非法 JSON、超时/鉴权失败、Token 与费用计算、任务取消、生成结果转入编辑器，以及斐波那契错误大答案的双语言校准。安全分支覆盖空答案回填、尾随空白规范化、无锚点、双解分歧、单语言失败、CE、RE、TLE、MLE 和输出超限。CI 在 Ubuntu、Python 3.10 和 G++ 环境执行 Ruff、格式检查与 pytest，并设置 85% 覆盖率门槛。

## 九、安全边界

本项目的进程组、资源限制、命令白名单和临时目录可以满足课程本地验收，但不能等同于内核级强隔离沙箱。若部署到公网，应把判题执行迁移到容器或专用沙箱，并增加只读根文件系统、用户/网络命名空间、seccomp、cgroup、作业队列、审计持久化与反向代理安全配置。

## 十、总结

本实验把异步 Web API、数据库、操作系统进程管理、权限审计和大模型工作流整合为一个可运行、可测试、可演示的系统。实现的重点不是单纯“运行代码”，而是在明确 API 契约下正确处理并发、资源回收、权限优先级、数据一致性和失败路径。项目附带 VS Code Remote WSL 配置、演示种子数据、线下验收清单和持续集成流程，便于重复验证。

## AI 使用说明

本项目开发过程中使用了 AI 辅助进行需求梳理、代码实现、测试设计与报告排版。所有生成内容均通过静态检查、自动化测试或人工审阅验证；AI 模型密钥不写入仓库。验收演示中的 AI 命题结果也必须由管理员人工检查后才能保存为正式题目。
